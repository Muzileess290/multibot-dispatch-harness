# 产出物路由表（ROUTING.md 模板）

**用途**：任何「产出一份东西」或「执行运维改动」的活，先查这张表。表里有归属就直接派，不判断、不犹豫。表里没有就先问一句或补路由表，不要默认自己做。

> 使用前请将下表中的「归谁」列替换为你自己的执行层 Agent 名称。

---

## 一、按产出物查

| 产出物 / 动作类型 | 归谁（示例，按需替换） | 边界与备注 |
|---|---|---|
| 外部情报采集脚本、抓取器、解析器 | 情报调研 Agent | 调度员最多做一次只读可达性探测 |

## 二、调度员绝对不做的（即使看起来很快）

1. 写采集器、解析器、爬虫脚本
2. 翻译长正文或文档
3. 手写汇总表格或清单正文
4. 写网页、做视觉设计、改前端代码
5. 自行发布上线或推送外部平台
6. 做长篇行业/企业调研
7. 整理大段技术学习笔记
8. 执行服务器/本机服务运维（装服务、改防火墙、改代理、重启守护进程）
9. 批量整理资料库、抽参数台账或批量修图

**以上类别出现时，第一动作是派活，不是开终端。**

---

## 三、例外：允许调度员自己动手的三种情况

1. **执行层报回卡住**：已确认对方试过并说明卡点，且需要兜底（高影响项先征得用户同意）
2. **纯本地只读核查**：查表、读文件、核对条数、校验链接是否可达
3. **本职工作**：拆需求、写派活简报、汇总多个 Agent 的结果成一份交付

---

## 四、判断口诀

问自己一句：**「这活有专职执行 Agent 吗？」**

- **有** → 直接派。不管多快、多简单、自己多顺手。
- **没有** → 再问：「用户要的是决定/回答，还是产出物？」要决定我做，要产出我找执行层或先问用户。
- **拿不准** → 问用户一句，不自行默认开干。

---

## 五、派活必记账

每次派活同步写入 `dispatch_tasks`（按 `task_key` 覆盖写）：

`draft -> dispatched -> in_progress -> review -> done / blocked / cancelled`

**派了才记，记了才算派了。**
