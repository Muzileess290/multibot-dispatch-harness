# 多指令并行拆分

## 步骤

1. **先拆指令，不排成串行队列。**
   逐条提取目标、产出、涉及文件/表、依赖关系与负责 Agent。必须先有 A 才能做 B 的标为**串行**，其余标为**并行候选**。*（坑：把多条指令留在同一个 turn 里顺序推进会白白耗时。）*

2. **先判写冲突，再决定并行。**
   列出每条指令要写的文件、目录与数据库表/唯一键；写同一文件或同一无唯一键表的不并行，只读任务可自由并行。

3. **按层级选并行方式：优先跨 Agent，其次同 Agent 子任务，最后串行。**
   - **首选跨 Agent 派活**：各执行层 Agent 拥有独立会话与上下文，天然真并行。
   - **其次同 Agent 子任务**：留在调度员手里的独立活按宿主并发上限（如 `taskLimit` / `concurrentTurns`）开子任务；不支持并发时只能串行。
   - **最后串行**：仅在存在前置依赖或写冲突时使用。

4. **写死每个并行任务的边界。**
   每个任务简报必须写清输入、输出路径、验收标准、不许碰的文件/表；子任务看不见主对话，且可能共享工作目录，不写边界会互相覆盖。

5. **按波次处理依赖。**
   无依赖任务一次全开；有依赖任务等前置产出验收通过后再开。

6. **立即发回执。**
   开完立刻用短表告知用户：开了几个并行任务、各自负责什么、哪些串行及原因。

7. **逐路核验再合并。**
   逐个核查产物是否存在、路径和表行数是否正确、有无覆盖或遗漏，再合并成一份交付；绝不把空结果当完成。

8. **外发前停。**
   并行会放大误发风险，所有外发、发布、提交动作必须先获用户批准并写 `outbox_receipts`。

## 自检清单

- [ ] 每条指令都有明确归属（跨 Agent / 子任务 / 串行波次）。
- [ ] 没有两个并行任务写同一文件或同一无唯一键表。
- [ ] 同 Agent 并发数未超宿主上限。
- [ ] 已向用户发出并行与串行拆分的即时回执。
- [ ] 每路产出均已按文件路径或表行数核验，无空结果冒充完成。
- [ ] 只有一条独立指令时不硬拆，直接按单任务推进。
